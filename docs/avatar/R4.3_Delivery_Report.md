## 2. Root-cause findings
- **Marker vs Visible Fingertip (Phase A)**: `ArmIKController.ts` was falling back to projecting a mathematical extension off `LeftHandIndex3` instead of tracking the actual node `LeftHandIndex4`. *Root Cause*: `LeftHandIndex4` exists in the GLB hierarchy but was completely missing from `CanonicalBones` in `boneMap.ts`. I added the node to the canonical registry, natively resolving the offset.
- **IK Target Overwrite Cycle (Phase B)**: The arm solver previously deduced a virtual target by blindly subtracting a fixed scalar length along the target-to-shoulder vector. *Correction*: Introduced an iterative bounding loop (up to 4 passes) that respects the true world offset between the wrist and the tip initialized recursively by the `HandController`. 
- **Backward Hand Orientation (Phase C)**: Wrist orientations were calculated blindly after the arm solver had spun the parent hierarchy unpredictably. *Correction*: `deltaQuat.setFromAxisAngle()` accurately isolates the shortest mathematical rotation aligning `wrist->tip` direction with the target ray organically on each loop constraint.
- **Elbow Twisting & Flipping (Phase D)**: Elbow planes were mapped relying on target position scalars (LERP heuristics between gravity and outward). *Correction*: Changed the natural pole constraint to natively inherit the Avatar's root `Spine` orientation vector mapping `X: Outward, Y: Slight Down, Z: Backwards`, keeping elbow structure independent from fingertip goals safely preventing unprompted inversion.
